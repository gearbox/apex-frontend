# CI test-suite architecture

## Verification topology

`Verify / verify` is the stable required check. It succeeds only when all of its
required lanes succeeded:

```text
quality ────────────┐
unit ───────────────┼──> Verify / verify
build ──> chromium ─┤
       └> webkit ───┘
```

`quality`, `unit`, and `build` start from independent clean checkouts. `build`
generates the production output once and uploads only `build/`; both browser
lanes download that artifact and serve it with `pnpm preview`. This keeps the
browser checks on the exact output that passed the build lane rather than
silently rebuilding it.

The jobs deliberately retain one Playwright worker each. Chromium and WebKit
gain parallelism from separate GitHub runners, not from competing browser
processes on a constrained runner. Each lane installs only its own engine.

## E2E browser coverage matrix

The suite uses Playwright tags in test titles/options. Untagged browser-neutral
tests run once in desktop Chromium; tags add coverage only where browser or
mobile behavior is meaningful.

| Coverage category | Desktop Chromium | Mobile Chromium (Android/PWA) | Mobile WebKit (iOS/PWA) |
| --- | --- | --- | --- |
| Browser-independent admin, API-state, profile, jobs, full create/library/session regression suites | Full canonical suite | — | — |
| Auth login, session isolation, generation submission, library load, session provisioning, offline transitions | Yes | Yes (`@cross-browser`) | Yes (`@cross-browser`) |
| Desktop navigation | Yes (`@desktop`) | — | — |
| Touch/mobile layout, mobile project/library interactions, standalone-layout emulation | — | Yes (`@mobile`) | Yes (`@mobile`) |
| Android/Chromium service worker, manifest/cache, lifecycle, frame-media, mobile billing checks | — | Yes (`@mobile-chrome`) | — |
| iOS install onboarding and dismissal persistence | — | — | Yes (`@mobile-webkit`) |

This is intentionally not a desktop-only shortcut: the PR workflow still
requires Android/Chromium PWA behavior, iOS/WebKit install behavior, and the
critical mobile journeys in both engines. The scheduled Playwright canary
continues to evaluate a newer Playwright package independently; it does not
replace this coverage or update the pinned 1.57.0 baseline.

## Generated-source contract

`pnpm generate` is the sole preparation command for Paraglide and SvelteKit
derived sources. `pnpm check` includes it for local ergonomics. The unit and
build lanes call it explicitly so no lane depends on files generated by an
earlier job. The quality lane asserts the required Paraglide entry points after
its check.

## Flake prevention

The E2E suite does not use arbitrary browser waits. Image-picker selections
wait for the selectable controls to become visible; the library filter arms its
request waiter before the click; and the frame extraction scenario no longer
races a one-second timer. CI retries were reduced from two to one after those
observable synchronization points were introduced. A retry remains diagnostic
evidence to investigate, not a passing condition to rely on.

## Timing baseline and follow-up measurement

The pre-refactor baseline recorded in the CI optimization brief was a successful
PR wall clock of about **10m16s**: check 19s, lint plus format 18s, unit 2m13s,
build 26s, browser install 54s, and serial E2E 5m45s. The dominant specs/projects
were not available from GitHub Actions logs in this environment because `gh` is
not authenticated.

The expected critical path is now `build -> max(e2e-chromium, e2e-webkit)`, while
quality and unit run in parallel with build. Exact after timings must be captured
from the first PR run; do not claim an observed speedup until then. Record each
job duration and any retry in the PR before considering Chromium sharding or
unit-suite changes.
